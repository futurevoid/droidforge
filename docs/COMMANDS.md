# droidforge - Command reference

Every command droidforge sends to a phone or runs on the host must be listed here, implemented in the
simulator (`adb/sim.py`), and carry a status. Do not invent device commands in code; add them here first.

Status:
- **L** - used by `legacy/cnrom_fix.py`, exercised against the mock phone (syntax known-good; the real Neo 8
  ran parts of it).
- **S** - confirmed from a cited source; not yet run on the owner's phone.
- **V** - VERIFY ON DEVICE before relying on it (plausible, not confirmed). The owner runs the Phase 9
  checklist and flips these to S/OK. Code must handle failure of any V command gracefully (clear message, no
  partial state without undo).

`<p>` = package, `<u>` = user id (always `0`), all device commands run via `adb -s <serial> shell '<cmd>'`.

**This file is the allowlist (P8).** `droidforge/engine/guard.py` holds one regex per write command below
(generated by hand from these tables, kept in sync by `tests/test_guard.py`, which parses this file). Rows whose
command only reads (`get`, `list`, `dumpsys`, `getprop`, `cat`, `resolve-activity`, `am start` of a settings
screen) are **allowed reads**; everything else is an **allowed write** and must declare `touches` (P10).
Anything not matching is refused at runtime. The "Forbidden" section at the end can never be added.

## Forbidden (P9) - never implement, never add to the allowlist

| Command / technique | Why |
|---|---|
| `app_process` with any droidforge DEX; `IActivityManager.updatePersistentConfiguration*` / `updateConfiguration` | Incident 2026-09-25: writing the persisted global configuration broke ColorOS Settings until "Reset all settings" |
| `settings put system system_locales`, `setprop persist.sys.locale`, `resetprop persist.sys.locale` | Config-level locale writes; the user sets the language in Settings |
| `pm grant <any> android.permission.CHANGE_CONFIGURATION` (MoreLocale etc.) | Same effect as above, through a third-party app |
| `cmd locale set-app-locales` on system packages or overlays; any "all packages" locale pass | Legacy menu `e` did this; adds risk, no benefit once the device language is English |
| `cmd overlay enable\|disable\|fabricate\|set-priority` | Changes the ROM's resource overlays (UI) |
| `cmd uimode night <mode>` as a "repair" | Repair toggles are side changes (P7); night mode is the user's setting |
| `pm clear <system package>` | Wipes system app state; not needed by any feature |
| Blanket `settings put` restores from a dump | Writes hundreds of keys; use Settings > Reset all settings instead |
| **Instructing the user to enable "Disable permission monitoring" / "Disable system optimization" / any developer-option switch; writing the setting or prop behind it** | **Root cause of the 2026-09-25 incident (owner confirmed): it broke the ColorOS Settings and permission UI** |
| **Display / UI (P9b):** `settings put` on `font_scale`, `font_variation_settings`, `display_density_forced`, `peak_refresh_rate`, `min_refresh_rate`, `window_animation_scale`, `transition_animation_scale`, `animator_duration_scale`, `icon_blacklist`, `ui_night_mode`, `dark_theme*`, `theme_customization_overlay_packages`, `material_color*`, `key_ux_icon_config`, `wallpaper*`, `navigation_mode`, `time_12_24`, `accessibility_display_*`, `high_text_contrast_enabled`, any key containing `color`, `theme`, `font`, `icon`, `density`, `refresh`, `animation`, `wallpaper` | Owner decision 2026-09-25: droidforge never changes how the phone looks |
| `wm density`, `wm size`, `wm font-scale`, `cmd display ...` writes, `cmd uimode ...` writes, `cmd wallpaper ...`, `cmd theme ...`, `cmd color_display ...` | Same |
| `settings put` on time/date keys (`auto_time`, `auto_time_zone`, `time_zone`, `date_format`) | Owner decision: time settings are only opened, never written |
| `resetprop`/`setprop` on display, density, locale, font, theme or UI props (`ro.sf.lcd_density`, `persist.sys.locale`, `persist.sys.*font*`, `*theme*`, `*dpi*`, `*density*`) | P9 / P9b |
