# Incident 2026-09-25 - ColorOS Settings UI broken by the legacy tool

Device: realme Neo 8 (RMX8899), China ROM, Android 16, no root. Tool: `legacy/cnrom_fix.py`, menu `e`
("Force English everywhere").

## What the user saw

- Settings showed stock-Android-looking pages instead of ColorOS ones (e.g. an AOSP "Display" page), toggles
  rendered "off" while their state said "On", washed-out colours.
- App-info > Permissions (PermissionController) rendered pale/low-contrast, light while the phone was in dark mode.

## What menu `e` changed

1. **Device language** through the embedded DEX (`cn.LocaleSetter`, run with `app_process` as shell):
   `IActivityManager.updatePersistentConfiguration(Configuration)`. v1 built a blank `Configuration`; v2
   (shipped during the incident) started from `getConfiguration()`. Both write the **persisted global
   configuration**, which ColorOS extends with its own fields (OplusExtraConfiguration: material colour, UX icon
   config, font variation, dark-mode lightness ...).
2. Fallback path: `settings put system system_locales <list>`.
3. `cmd locale set-app-locales` on **every installed package** (framework, SystemUI, Settings, overlays included).
4. Gboard switched in, Chinese IMEs disabled.

## Elimination

| Suspect | Test | Result |
|---|---|---|
| Per-app locale overrides | removed from all packages (`fix_settings.py`, `undo_everything.py`) | still broken |
| Package state (disabled/removed/suspended/neutered) | all packages back to the first snapshot | still broken |
| Font scale / dark-mode lightness | checked: 1.0 and healthy `0.0 / 27.0 / 100.0` | not the cause |
| Device language itself | switched to Chinese through Settings | still broken |
| "Disable permission monitoring" developer switch | owner confirmed | not the cause |
| **Persisted global configuration / system locale settings** | **Settings > Reset all settings** | **FIXED** |

Evidence in the live config before the fix: `mMaterialColor= 0` while `settings system material_color_value`
was `17179869184` (0x400000000). No app, reboot, night-mode toggle, colour/theme re-apply restored it.

## Root cause (by elimination)

Writing the persisted global `Configuration` from outside the Settings app (`updatePersistentConfiguration`
through the DEX) put ColorOS's extended configuration into a state that ColorOS does not repair on its own.
`settings put system system_locales` is the other config-level write and cannot be excluded.
Only "Reset all settings" (or a factory reset) restored it.

## Rules that follow (enforced in droidforge; see SPEC P7-P12)

1. **Never write the global/persisted `Configuration`.** No `updatePersistentConfiguration`, no
   `updateConfiguration`, no `app_process` helpers, no MoreLocale / `CHANGE_CONFIGURATION` grants.
2. **Never write `system_locales`** or `persist.sys.locale`.
3. The device language is set by the user in **Settings > Language** (it works on this ROM - the owner verified
   English is offered there). droidforge only opens that screen and verifies the result read-only.
4. **Per-app locales only on user-picked, non-system apps.** Never on framework, SystemUI, Settings,
   PermissionController, overlays/RROs, or any package from `pm list packages -s`.
5. **No bulk "every package" writes of any kind.**
6. Every command must match the allowlist in `COMMANDS.md`; the executor refuses anything else.
7. Snapshot `settings system/secure/global` + global configuration before and after every plan; any change
   outside the plan's declared keys is reported as a regression with an undo offer.
8. Post-plan health check (Settings home activity, PermissionController trampoline, `mMaterialColor`, font
   scale, night mode) - a regression stops the session.
9. The recovery advice for config damage is **Settings > Reset all settings** (keeps apps and data), shown by
   `droidforge doctor` when the health check fails.
